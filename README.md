# score it

Веб-приложение для командной оценки трудозатрат в часах и планирования спринтов. Организатор работает под своей учётной записью, участники подключаются к голосованию без регистрации по уникальной ссылке.

## Возможности MVP

- проекты и массовая загрузка задач в формате `номер | название`;
- импорт неоценённых задач из CSV/XLSX EVA в проект или сразу в очередь комнаты;
- описание задачи и ссылка в EVA на карточке участника;
- необязательное разделение задач на аналитику, разработку и тестирование;
- одноразовые приглашения организаторов через Django-админку;
- изоляция проектов, задач, комнат и спринтов по владельцу;
- пакетное добавление задач в упорядоченную очередь голосования;
- асинхронное прохождение очереди каждым участником в своём темпе;
- индивидуальная навигация назад/вперёд с сохранением выбранных оценок;
- проверка пропущенных задач перед завершением оценки участником;
- настраиваемый минимум голосов перед раскрытием карт;
- автоматический переход к следующей задаче после сохранения оценки;
- публичные комнаты голосования;
- вход участника по имени без учётной записи;
- персональная ссылка для продолжения оценки на другом устройстве без создания дубля;
- часовая шкала `0, 1, 2, 4, 8, 12, 20, 32, 52`;
- скрытые голоса, раскрытие и повторный раунд;
- сохранение точного среднего как суммы голосов и их количества;
- итоговая оценка из часовой шкалы: ближайшая карточка к среднему, при равном расстоянии — большая;
- спринты со статусами «Планируется», «Активен» и «Завершён»;
- фильтры бэклога и ручное завершение задач;
- архивирование и восстановление старых комнат и спринтов;
- безопасное удаление задач, комнат и спринтов организатором;
- полный прогресс каждого участника по очереди голосования;
- контроль ёмкости, остатка и превышения плана спринта отдельно для аналитики, разработки и тестирования;
- копирование комнат без голосов, копирование настроек спринта без дат и задач;
- перенос задач между спринтами с сохранением истории;
- общий дашборд активной работы организатора;
- плановая ёмкость спринта в часах и сумма оценок;
- выгрузка спринта в Excel;
- фоновое обновление через HTTP polling без Redis и WebSocket;
- локальный запуск в Docker и production-запуск через Passenger/WSGI.

## Быстрый запуск в Docker

```bash
cp .env.example .env
docker compose up --build
```

После запуска приложение будет доступно по адресу <http://localhost:8000>.

Создание организатора:

```bash
docker compose exec web python manage.py createsuperuser
```

## Запуск без Docker

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

## Тесты

```bash
python manage.py test
```

## Как проходит пакетная оценка

1. Импортируйте в проект список задач.
   Для однотипного списка сначала выберите направление. В смешанном списке используйте префиксы `[Аналитика]`, `[Разработка]` и `[Тестирование]` в нужных строках.
2. При создании комнаты выберите задачи и укажите минимум голосов. Все неоценённые задачи уже отмечены.
3. Отправьте участникам одну публичную ссылку и нажмите «Начать оценку». Голосование откроется сразу по всей очереди.
4. Каждый участник проходит задачи независимо, используя кнопки «Назад» и «Вперёд». Голоса и текущая позиция сохраняются.
5. Кнопка «Ссылка для продолжения» позволяет сохранить персональный адрес и восстановить ту же сессию на другом устройстве.
6. На последней задаче приложение проверяет пропуски: при необходимости ведёт к первой неоценённой задаче, а после заполнения всей очереди показывает кнопку «Завершить оценку».
7. Организатор видит прогресс по каждой задаче. После достижения минимума он раскрывает карты, видит среднее голосов и итог по шкале, затем сохраняет результат.
8. Из комнаты организатора можно выгрузить все принятые оценки в CSV или XLSX: `Код задачи`, `Наименование`, `Итоговая оценка, ч`. Выгрузка использует принятый раунд выбранной комнаты независимо от более поздних оценок этой задачи в других комнатах.

Итог выбирается из `0, 1, 2, 4, 8, 12, 20, 32, 52` по расстоянию до точного среднего: `25 → 20`, `26 → 32`, `29 → 32`. При равном расстоянии выбирается большее значение. Итог `0` возможен только при всех нулевых голосах; при положительной сумме минимум — `1`. Без голосов оценка отсутствует. Предварительное округление среднего не влияет на выбор карточки.

Бэклог, спринты и выгрузки используют один расчёт. Загрузка спринта и компетенций — сумма итоговых оценок отдельных задач; сама сумма к шкале не округляется. Исходные голоса, сумма и их количество сохраняются. Правило работает и для ранее принятых оценок без миграции данных и повторного голосования; загрузка существующих спринтов пересчитывается при открытии. После обновления выгрузите файлы заново. В импортах, которые ищут колонку по имени, используйте новый заголовок `Итоговая оценка, ч` вместо `Средняя оценка, ч`.

Если участник потерял персональную ссылку, организатор может скопировать её в карточке участника. Кнопка «Обновить» выпускает новую ссылку и отзывает старую; участник, его прогресс и голоса при этом сохраняются.

## Команда и расчёт ёмкости спринта

В проекте появился раздел **«Команда»**. Добавьте ФИО, компетенцию
(аналитика, разработка АБС/BE/FE, тестирование или дефект; старые записи разработки остаются неуточнёнными), аллокацию от 0 до 100% и часы в день.
Эти значения используются по умолчанию в новых спринтах. Сотрудники проекта
не требуют учётных записей и учитываются отдельно от участников голосования.

При создании спринта выберите **«Рассчитать по сотрудникам»** и обе даты.
Активные сотрудники копируются в состав спринта с нулевым отсутствием.
На вкладке **«Команда и ёмкость»** можно добавить или исключить сотрудника,
изменить его компетенцию, аллокацию, часы в день и рабочие дни отсутствия
именно в этом спринте. Половина дня указывается как `0,5`.

Расчёт для каждого сотрудника:

`Часы до резерва = max(0, рабочие дни − дни отсутствия) × часы в день × аллокация / 100`

`Часы для плана = часы до резерва × (1 − резерв / 100)`

Результат сотрудника округляется до сотых часа, затем часы суммируются
по компетенциям. Например, 10 рабочих дней, 2 дня отсутствия, 8 часов в день,
аллокация 75% и резерв 20% дают 48 часов до резерва и 38,40 часа для плана.
Нулевая аллокация и ноль рабочих дней дают нулевую ёмкость. Если нет дат или
сотрудников, ёмкость остаётся неопределённой и отображается как «—».

По умолчанию считаются понедельник–пятница включительно; праздники автоматически
не загружаются. Поле **«Рабочих дней по календарю»** позволяет задать точное
количество с учётом праздников и рабочих суббот. Резерв по умолчанию равен 0%.
Для выделения 10% на дефекты и 10% на операционные задачи укажите суммарный
резерв 20%. Он вычитается один раз. Задачи, на которые выделен этот резерв,
не следует дополнительно включать в план, использующий оставшуюся ёмкость.
Квоты из EVA отображаются отдельно как количество задач и доля состава спринта; они не вычитают часы и не изменяют резерв. Если дефекты включены в план, не резервируйте те же часы повторно.

Изменения справочника сотрудников не пересчитывают существующие спринты:
ФИО, компетенция, аллокация и часы сохраняются в составе каждого спринта.
Снятие признака «В команде» исключает сотрудника только из новых составов.
Повторное добавление всей команды дополняет состав, сохраняя уже введённые
параметры. Завершённые и архивные спринты доступны для просмотра без изменения
команды и календаря. Копия спринта получает текущую активную команду проекта,
нулевое отсутствие и тот же резерв, но создаётся без дат, задач и календарной
поправки. Для расчёта её ёмкости нужно указать новый период.

На вкладке **«Команда и ёмкость»** можно корректировать ФИО, компетенцию,
аллокацию, часы в день и отсутствие каждого участника, добавлять участников
из справочника или только в этот спринт. Изменения применяются к выбранному
спринту; временные участники не добавляются в справочник проекта.
Здесь же доступен ручной ввод часов по всем компетенциям: кнопка
**«Применить ручную ёмкость»** включает ручной режим и сохраняет состав команды.
Пустое поле — лимит не задан, ноль — доступных часов нет. Резерв применяется
только при расчёте по сотрудникам. Вернуться к нему можно через поле
«Способ расчёта» в блоке календаря. Ручные значения при этом сохраняются.

В режиме расчёта по сотрудникам существующие индикаторы плана, остатка,
превышения и предварительный расчёт выбранных задач используют рассчитанные
часы. «Отчёт по ёмкости» дополнен листом «Команда» с параметрами и результатом
каждого сотрудника. «Excel для EVA» сохраняет прежний формат.

Миграция `0014_sprint_team_capacity` добавляет таблицы команды и параметры
расчёта. Все существующие спринты остаются в ручном режиме с прежними ёмкостями,
задачами и оценками. Переключение на расчёт по сотрудникам выполняется отдельно
в нужном спринте; ручные значения сохраняются для обратного переключения.

## Ручная синхронизация с EVA

В EVA экспортируйте CSV/XLSX «все поля». Загрузить файл можно в проекте,
комнате оценки или спринте. Все три входа обновляют одни и те же задачи проекта.
В очередь комнаты добавляются только неоценённые, незавершённые задачи без спринта.

| Колонка EVA | Поле score-it |
|---|---|
| `Код` | Номер задачи, уникальный в проекте |
| `Идентификатор объекта` | `CmfTask:UUID`, проверка личности задачи и ссылка EVA |
| `Наименование` | Название |
| `Логический тип.Имя логического типа` | Тип задачи |
| `Текст` / `Текст без html` | Описание |
| `Оценка задачи, час` | Текущая оценка, часы |
| `Тип квоты` | Произвольное название квоты из EVA |
| `Спринты` / `Спринт` | Название спринта |
| `Статус.Имя статуса` / `Статус задачи` | Состояние задачи EVA |

Колонки определяются по заголовку, а не позиции. Общие поля задачи обязательны;
квота, спринт и статус могут отсутствовать (в импорте со страницы спринта статус
обязателен). Отсутствующая колонка не очищает сохранённое значение. Отдельные поля
EVA `Оценка`, `Story Point`, `Статус` не подменяют указанные выше поля.

Правила повторного импорта:

- Сопоставление по коду внутри проекта с проверкой UUID. Новый код создаёт задачу,
  повторный обновляет название, описание, тип, квоту и заполненную оценку.
  Один UUID у разных кодов или новый UUID для существующей задачи — конфликт.
- Положительная оценка EVA заменяет текущую, в том числе у запланированной задачи.
  Допускаются часы до 999999,99 с точностью до сотых, без округления к шкале Poker.
  История голосования не изменяется; новое принятое голосование заменяет импортированную оценку.
- Числовой ноль EVA (`0`, `0.0`, `0,00`) означает «Не оценена», в том числе при
  повторном импорте: текущая оценка и её агрегаты сбрасываются. Раунды и голоса
  сохраняются в истории. У задачи в активном спринте исчезают оценённые часы, но
  назначение меняется только по колонке «Спринты».
- Пустая ячейка создаёт новую задачу без оценки, но сохраняет оценку существующей:
  она могла ещё не попасть из score-it обратно в EVA.
- Назначение обновляется только при наличии колонки спринта. Одно название связывается
  со спринтом этого проекта по точному имени без учёта регистра. Незнакомое имя создаёт
  спринт в статусе «Планируется», без дат, команды и ёмкости; их нужно заполнить отдельно.
  Не используйте разные сокращения одного имени, например `2026.20` и `2026.20.abs`.
- Пустая ячейка спринта (также `Нет`, `—`, `-`, `[]`) снимает текущие назначения.
  При переносе сохраняется старая строка с отметкой и целью переноса; при снятии —
  отметка «Исключена по данным EVA». Эти строки не входят в часы и квоты старого спринта.
- Несколько спринтов в ячейке (разделители `;`, `,`, перевод строки или JSON-список)
  и совпадающие имена нескольких локальных спринтов — конфликт всей строки.
  Автоматический выбор «последнего» спринта не выполняется.
- EVA является источником актуальных оценок и назначений, в том числе для задач
  завершённых/архивных спринтов. Разрешены обновление оценки, перенос из такого спринта,
  назначение в него и снятие назначения по пустой ячейке. Состав, квоты и итоговые часы
  старых спринтов отражают импортированные данные и могут изменяться. Статус спринта,
  признак архива, даты и ёмкость при этом не меняются. История голосования сохраняется.
- Задачи на текущем голосовании пропускаются: повторите импорт после его завершения.
  При пропуске существующей строки выставляется только служебная отметка непроверенной
  готовности, чтобы прежнее состояние аналитики не давало ошибочного допуска.
- Закрытый/выполненный/отменённый статус помечает задачу завершённой; открытый статус
  снимает эту отметку. Такие задачи не предлагаются для нового планирования.
- Некорректные оценки и неизвестные типы пропускаются с предупреждением. Ошибки обязательных
  полей или конфликтующие дубликаты отклоняют весь файл до записи. Задачи вне файла не удаляются.
  Повторный импорт того же файла не создаёт дубликатов задач, спринтов или назначений.

Типы «Разработка АБС», «Разработка BE», «Разработка FE», «Дефект» сохраняются отдельно.
«Системный анализ» и «Аналитика» дают тип «Аналитика»; варианты тестирования DEV/TEST —
«Тестирование». Общая «Разработка» и «Разработка Битрикс» остаются неуточнённой разработкой.
Существующие задачи/сотрудники общей разработки не переводятся в АБС автоматически.
В команде и настройках спринта доступны отдельные ёмкости новых типов. При необходимости
уточните специализации сотрудников и ручные ёмкости перед следующим планированием.

Квоты показаны в спринте в абсолютном количестве задач и процентах от **всего текущего
состава**, включая задачи без оценки. Пустая квота показана как «Не указана».
История переносов исключается из знаменателя; проценты округляются до сотых.
Квоты не являются процентами часов и не меняют расчёт резерва.

Импорт показывает количество добавленных, обновлённых, неизменённых задач, изменённых
назначений, новых спринтов и пропусков с причинами. CSV поддерживает UTF-8, UTF-16 с BOM,
Windows-1251 и разделители `;`, `,`, табуляцию. XLSX должен содержать один лист задач.
Ограничения: 10 МБ, 5000 строк, 512 колонок. HTML описания преобразуется в обычный текст.

### Допуск к оценке после аналитики

В форме создания комнаты и добавления задач в существующую комнату показаны только
неоценённые, незавершённые задачи, не включённые в текущий состав спринта и прошедшие
проверку готовности. Сохранённая оценка, в том числе нулевая оценка голосования,
исключает задачу из этих списков. При отправке формы условия проверяются заново.
Выбор компетенции (включая «Без типа») работает вместе с поиском по номеру/названию.
В очередь попадают только отмеченные задачи, видимые по фильтрам; «Выбрать все» и
«Снять» действуют на видимую часть списка. Пустой результат фильтра отключает отправку.
Проверка поведения фильтров: `node --test tests/task-picker.test.cjs`.

Для задач EVA типов «Разработка АБС», «Разработка BE», «Разработка FE» и
«Тестирование» проверяется выполнение связанной аналитики. Задачи аналитики,
дефекты, общая разработка и задачи, созданные вручную без идентификатора EVA,
сохраняют прежнее поведение. Тип берётся из «Логический тип.Имя логического типа»;
префикс `[QA]` не превращает тестирование в разработку.

Сопоставление по названию — временное правило, пока экспорт не содержит ID родителя:

- Если заполнено `Родительская задача.Наименование`, используется её точное название.
  Иначе из названия задачи убираются начальные `[SA]`, `[ABS]`, `[BE]`, `[FE]`, `[QA]`.
  Только у `[QA]` убирается конечное `DEV`/`TEST`, в том числе с дефисом перед ним.
  Регистр и повторные пробелы не учитываются; похожие названия не объединяются.
- Учитываются проект score-it, `Проект.Имя объекта` и `Epic.Наименование`.
  Конфликтующие или неполные сведения о проекте/эпике не дают допуска.
  Эти три дополнительных поля импортируются при наличии колонок; отсутствующие
  колонки сохраняют прежние значения, пустые ячейки очищают их.
- Все найденные аналитические задачи должны иметь явный статус «Выполнена» или
  «Завершена» (также `Done`/`Completed`). «Закрыта», отмена, ревью, оценка в часах,
  локальная отметка завершения и `Кеш: Тип статуса` не доказывают выполнения аналитики.
- При отсутствии аналитики или однозначного соответствия задача сохраняется в бэклоге,
  но не предлагается для оценки. Причина и коды найденной аналитики показаны в бэклоге
  и комнате. При нескольких аналитических задачах ожидаем выполнения всех.

Импортируйте вместе с задачами также выполненную аналитику. Допуск рассчитывается
после обработки всего файла, независимо от порядка строк, и при открытии комнаты.
Используются последние успешно импортированные данные; онлайн-проверки в EVA нет.
Пропуски/конфликты импорта существующей задачи блокируют её допуск и использование её
как подтверждения выполнения аналитики до успешной повторной загрузки со статусом.
Совпадающие названия
разных функциональностей внутри одного проекта и эпика этот способ различить не может.

Правило действует при импорте в комнату, ручном добавлении, создании/копировании комнаты
и запуске нового раунда (в том числе для старой очереди). Начатое голосование и его
история автоматически не отменяются. Синхронизация оценок и состава спринтов продолжает
работать для всех импортируемых задач, независимо от готовности к новому голосованию.

Для установки примените миграцию `0016_eva_relationship_names` и повторно загрузите
выгрузку всех полей. Она добавляет поля названий родителя, проекта и эпика и отметку
непроверенной готовности; оценки и история миграцией не меняются.

### Обратная передача в EVA

Оцените новые задачи в комнате, затем спланируйте спринт. «Excel для EVA» сохраняет
прежние 11 колонок (код, название, тип, оценка, UUID, ссылка, спринт, даты, проект,
ID спринта score-it) в прежнем порядке и добавляет `Тип квоты` последней колонкой.
«Отчёт по ёмкости» дополнен квотой каждой задачи и листом «Квоты» с количеством и долями.
Текстовые значения в Excel записываются как текст, включая строки, начинающиеся с `=`.

Файл сам не изменяет EVA: обратная запись оценок и назначений выполняется имеющимся
локальным API-процессом, после чего новая выгрузка EVA импортируется обратно в score-it.
Это ручной цикл синхронизации; фонового обращения к EVA в приложении нет.

Миграция `0015_eva_sync_quotas_types` добавляет квоту и новые ёмкости, расширяет типы и
точность импортированной оценки. Старые голоса, оценки, назначения и ручные ёмкости
сохраняются. Новые ёмкости не заданы, квоты старых задач пустые до повторного импорта.

## Приглашение организатора

1. Суперпользователь открывает `/admin/` и раздел «Приглашения организаторов».
2. Создаёт приглашение, при необходимости указывая пометку «Для кого».
3. Копирует сформированную ссылку и отправляет её будущему организатору.
4. Пользователь переходит по ссылке и задаёт логин и пароль.
5. После регистрации он входит в приложение и работает только со своими проектами.

Приглашение одноразовое и действует 7 дней. Созданная по нему учётная запись активна, но не имеет признаков `is_staff` и `is_superuser`, поэтому не может войти в Django-админку.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DJANGO_SECRET_KEY` | Секретный ключ Django; обязателен в production |
| `DJANGO_DEBUG` | `1` локально, `0` в production |
| `DJANGO_ALLOWED_HOSTS` | Домены через запятую |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | HTTPS-адреса через запятую |
| `DJANGO_TIME_ZONE` | Часовой пояс, по умолчанию `Europe/Moscow` |
| `DATABASE_PATH` | Путь к SQLite-файлу |

## Production на REG.RU

Проект рассчитан на Python 3.12 и Phusion Passenger. Общая последовательность развёртывания:

```bash
git clone git@github.com:Parabe11um/score-it.git
cd score-it
/opt/python/python-3.12/bin/python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python manage.py migrate
.venv/bin/python manage.py collectstatic --noinput
.venv/bin/python manage.py createsuperuser
```

При последующих обновлениях:

```bash
git pull --ff-only origin main
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py collectstatic --noinput
touch .restart-app
```

В панели хостинга нужно выбрать Python 3.12, указать корень приложения и точку входа `passenger_wsgi.py`. Точные пути и домен заполняются при первой публикации.
